Read and follow `.claude/12sp/rules.md`.

Task: $ARGUMENTS

## Stages
1. **Preflight** — read `CLAUDE.md`, check git, and record the baseline.
2. **Reuse approved artifacts** (same task only, per the rules):
   - Approved `.12sp/plan.md` → skip requirements-reviewer, ui-designer, and solution-architect; use the plan's requirements, design, and recommended stages.
   - Otherwise, approved `.12sp/ui.md` → skip ui-designer only.
   Tell the user which stages are being skipped and why.
3. **requirements-reviewer** (if not skipped). If not ready for design, stop and ask the blocking questions.
4. **Build the stage plan.** Always: solution-architect (unless skipped), developer, code-quality-reviewer, test-writer (verification mode), acceptance-reviewer. Conditionally, from requirements-reviewer's "Relevant downstream stages" (or the approved plan):
   - `ui-designer` (ux mode) — user-facing UI, no approved ui.md; before solution-architect
   - `test-writer` (characterization mode) — changes existing behavior in code with little or no test coverage; after solution-architect, before developer
   - `security-reviewer` — after developer; include unless clearly not applicable
   - `compliance-reviewer` — new personal-data handling; after security-reviewer, before code-quality-reviewer
   - `user-manual-writer` — user-facing changes
   - `migration-planner` — stored data, external contracts, or a deployment sequence; runs last

   Show the stage list and wait for the user to confirm or adjust it.
5. **Run each stage in order.** If solution-architect proposes anything requiring approval, stop and get explicit approval before developer runs.
6. **Wrap up** per the rules, including the migration/launch plan. Offer to archive this run's `.12sp/` files. Mention `/12sp-post` for later, once the change is live and usage data exists.
